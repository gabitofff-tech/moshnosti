# Контур — производственные мощности

Первая локальная рабочая версия по схеме и четырём Excel-образцам пользователя.
Python 3.12+, FastAPI, SQLite, обычный браузер. Внешние веб-сервисы для расчёта не требуются.

## Запуск

```bash
cd /workspace/moshnosti
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Открыть порт 8000 в браузере на машине запуска. Сервер по умолчанию доступен только локально.
`data/capacity.sqlite` хранит введённые данные, `calendars/*.json` — календари.
При первом запуске база пуста. Копируйте базу при остановленном приложении вместе с календарями для резервной копии.
`CAPACITY_DB` задаёт другой путь к базе. Инструкция запуска не создаёт и не требует Git worktree.

## Работа

1. Создать предприятие. Можно добавить пять или больше предприятий, их данные хранятся отдельно.
2. Внести **весь парк**: модель/группа, количество взаимозаменяемых единиц, категория нормативов. Потери для каждой сменности подтягиваются из таблицы 1; их можно исправить.
3. Создать изделия. Ввести программу **для выбранного периода**. Годовая и месячная программы независимы: автоматического деления на 12 нет. Ноль означает отсутствие выпуска; пустое значение — неизвестную программу.
4. Добавить корневые ДСЕ и вложенные сборки/детали. Количество на изделие — произведение количеств по ветви. Повторное вхождение детали в разных ветвях учитывается отдельно.
5. Выбрать ДСЕ и ввести операции, выбранную модель и **станко-минуты на одну ДСЕ**. Пустая норма — неизвестная, нулевая — явно нулевая. Нормы сборки можно внести в корневую ДСЕ с количеством 1.
6. Альтернативы — перечень допустимого оборудования; Ctrl/Cmd выбирает несколько. Назначение конкретной модели делается явно в колонке «Выбранное оборудование». Альтернатива сама не получает дополнительную загрузку. Применимость и одинаковую норму на альтернативном станке подтверждает пользователь; если норма отличается, её меняют при выборе.
7. Сохранить. Открытие отчёта также сохраняет изменения. При одновременном изменении с другого окна сервер отклоняет устаревшую версию.
8. В каждом отчёте есть настройки коэффициента, округления и подписей. Настройки общие для взаимосвязанных отчётов. Экспорт — отдельный XLSX для каждой формы.

## Четыре таблицы

- **1. Фонд**: рабочие часы календаря × сменность × (1 − потери/100). Первичный лист — полный парк предприятия; отдельный лист «Нормативы потерь» сохраняет весь исходный классификатор из образца.
- **2. Трудоёмкость**: полное количество ДСЕ × машинные минуты / 60 × программа. Excel повторяет шестиколоночный блок для каждого изделия; итоги по всем изделиям и всем операциям на каждой модели.
- **3. Загрузка и потребность**: Кз = суммарная потребность / (действительный фонд одной единицы × количество). Расчётное количество = потребность / допустимый коэффициент / фонд одной единицы. По образцу принятое количество округляется вниз при дробной части ≤ 0,2, иначе вверх. Баланс = наличие − принятое количество. При нулевом общем фонде Кз не определён, это не 0%.
- **4. Мощность**: максимум **общих** Кз по оборудованию, участвующему в изготовлении изделия. M = программа / Кзmax × допустимый коэффициент, округление до целого (половина вверх, как ROUND в Excel). **Постоянная структура ассортимента:** программы всех изделий масштабируются вместе. Результат не означает, что каждое изделие может занять весь парк независимо от остальных. При нулевой программе/отсутствии нагрузки мощность не определена.

По умолчанию коэффициент 0,95 и порог 0,2, как в образцах. Потери и коэффициент не дублируют друг друга: потери уменьшают календарный фонд, 0,95 используется при расчёте потребности и мощности.

Excel-файлы создаются из оригиналов в `templates/`: сохраняются шрифты, границы, шапки, объединения шапок и настройки страницы. Строки и блоки изделий расширяются под данные. Экспорт содержит рассчитанные значения, а не требующие пересчёта Excel формулы. Добавлен лист паспорта расчёта. Программа не обещает побитовую или пиксельную идентичность страниц при другом количестве строк/изделий, иных принтерах или шрифтах.

## Календарь

Включён **2026 год**, федеральная пятидневка, 40 ч: 247 рабочих дней, 1972 часа, 4 сокращённых дня. Переносы: постановление Правительства РФ от 24.09.2025 №1466; федеральные праздники — ст. 112 ТК РФ. Рабочий час сменности считается линейно, как в образце; круглосуточные и скользящие графики не моделируются.

Для другого года в разделе «Производственный календарь» внести нерабочие даты, рабочие выходные и сокращённые дни по подтверждённому источнику, указать основание. Формат ММ-ДД. Региональные/корпоративные исключения добавляются там же. Незагруженный год блокирует расчёт. Автоматическая синхронизация календарей из интернета **не реализована**; внешняя загрузка xmlcalendar.ru в этой среде возвращает 403.

```bash
CHROMIUM_PATH=/usr/bin/chromium .venv/bin/python tests/browser_smoke.py
```

Для браузерной проверки нужен установленный Chromium и системные библиотеки. Chromium не требуется приложению на сервере. Браузерный тест создаёт временную БД, запускает отдельный сервер и проверяет ввод, сохранение, изменение норм, 4 скачивания Excel и месячный календарь. Снимок — `docs/interface.png`. Четыре `docs/examples/*.xlsx` содержат только синтетические данные.

## Границы текущей версии

Реализован расчётный сценарий из текущего запроса. Это **не полная реализация большого ТЗ**: нет авторизации/ролей и серверного разграничения доступа, интеграции с корпоративными системами, импорта произвольных Excel, утверждений/аудита, версий сценариев, переналадок/партий, персонала и оптимизации перераспределения. SQLite хранит текущую версию данных; нет неизменяемых архивных расчётов. Пустые нормы и программы блокируют экспорт, но приложение не проверяет технологическую достоверность введённых данных. Не публикуйте этот сервер в сети предприятия до реализации доступа и эксплуатационных мер.

## Windows: запуск без Python (.exe)

В GitHub откройте **Releases**, скачайте **Moshnosti.exe** из последнего релиза (не архив Source code) и запустите двойным щелчком. Версия для Windows 10/11 x64. Python и установленный Excel не нужны; для работы используется ваш обычный браузер. Интернет после скачивания не требуется.

Откроется окно запуска и интерфейс в браузере. Окно запуска держите открытым; кнопка «Открыть программу» вернёт интерфейс, «Папка данных» откроет сохранения. Чтобы закрыть программу, сначала сохраните данные в браузере и нажмите «Завершить» в окне запуска.

Данные EXE: `%LOCALAPPDATA%\Moshnosti\capacity.sqlite`, календари — `%LOCALAPPDATA%\Moshnosti\calendars`, журнал — `application.log`. Обновление EXE не перезаписывает базу и изменённые календари. Для резервной копии завершите программу и скопируйте эту папку целиком. Данные прежнего запуска из исходников автоматически не переносятся: при остановленных версиях скопируйте старую базу и календари в указанные места. EXE не имеет цифровой подписи; перед распространением в организации нужна подпись/проверка по её правилам. Контрольная сумма сборки приложена к релизу в `SHA256SUMS.txt`.

### Как собирается Windows-версия

GitHub Actions **Windows EXE** запускается при обновлении `main` или вручную через Actions → Windows EXE → Run workflow. На Windows устанавливается Python 3.12 x64, выполняются тесты, PyInstaller собирает один EXE со встроенными шаблонами, веб-интерфейсом и исходным календарём. Затем **сам собранный EXE** выполняет `--smoke-test`: реальный локальный сервер, ввод кириллицы, месячный расчёт, четыре XLSX, перезапуск и проверка сохранения базы/календаря. Только успешная сборка публикуется в Releases; также доступен артефакт `Moshnosti-Windows-x64` в запуске Actions. `smoke-test.json` в релизе содержит результаты проверки именно этого EXE.

Сборка вручную на Windows из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt httpx==0.28.1
python -m unittest discover -s tests -v
.\scripts\build_windows.ps1
```

Результат — `dist\Moshnosti.exe`. Linux не используется для перекрёстной сборки Windows-EXE. Настройка доступа/подтверждений из большого ТЗ остаётся за границами локальной версии и не появляется от упаковки в EXE.

## Мониторинг предприятий и оценка переноса

Новая вкладка **«Мониторинг предприятий»** объединяет все предприятия **этой базы**, независимо от предприятия, выбранного слева. Период общий: год/месяц в верхней панели; сменность 1–3 — в мониторинге. «Обновить данные» заново читает сохранённые записи. Фильтр предприятия влияет на детальные таблицы, общие карточки остаются сводными.

Общая загрузка — **сумма потребностей / сумма фондов**, а не среднее процентов. Видны загрузка каждого предприятия, полный парк и группы сопоставимого оборудования. Локальные резервы и дефициты суммируются раздельно, поэтому свободный фонд одного станка не скрывает дефицит другого. В основных колонках резерв = max(F × допустимый Кз − D, 0), дефицит = max(D − F × допустимый Кз, 0). Физический резерв/дефицит относительно полного фонда также включены в Excel. Предприятия с неизвестной программой/нормами или ошибками помечаются «Неполные данные»: их мощность не предлагается как свободная; общая загрузка при таких пробелах не выдаётся за точную.

### Подготовка совместимости

В «Парке оборудования» заполните **код совместимости между заводами**, например `ТОК-ЧПУ-01`. Одинаковый код означает, что **пользователь подтвердил** технологическую применимость этих моделей для переноса. Регистр и пробелы по краям не учитываются. Название модели и категория нормативов потерь сами по себе такой связи не создают. Старые записи без нового кода продолжают работать в четырёх исходных отчётах и показываются в мониторинге, но не участвуют в предложениях переноса.

### Сценарий переноса

- «Варианты разгрузки» предлагает отдельные операции с перегруженного оборудования на совместимое оборудование другого предприятия. Предварительно нормы времени равны исходным. Это **независимые альтернативы**, их объёмы не складываются автоматически.
- «Выбрать» заполняет форму. Проверьте количество **ДСЕ**, оборудование получателя и его норму, затем нажмите «Добавить в сценарий и оценить». Можно выбрать операцию вручную, даже если её источник не перегружен.
- В сценарии вычитается время источника и добавляется время получателя по его норме. Несколько строк используют **один общий резерв**; превышение доступной мощности или исходной программы операции отклоняется. Изменение нормы может изменить общую потребность в часах — это отражается в «до/после».
- Сравниваются потребности, загрузка, резервы и дефициты, показывается парк после переноса. Программы, составы и нормы **не перезаписываются**. Это перенос отдельной операции, а не автоматически всей ДСЕ/всего маршрута.
- Черновик хранится только в текущей сессии интерфейса. Смена периода/сменности сбрасывает его. Для сохранения результатов скачайте общую таблицу: Excel содержит свод предприятий, парк, группы, паспорт, а при сценарии — строки переноса и состояние после.

Сценарий проверяет только станко-время. Люди, оснастка, качество, поставки, сроки и логистика требуют отдельного подтверждения. Это расчётная оценка, не утверждённое распоряжение на перенос и не автоматическая оптимизация.

**Обмен между компьютерами:** вкладка использует предприятия, введённые в одну локальную базу. Отдельные EXE на разных компьютерах не синхронизируются. Для реального сетевого мониторинга нужны общий сервер, авторизация/права и согласованный обмен данными; эта версия их не добавляет.

Дополнительная браузерная проверка: `.venv/bin/python tests/browser_monitoring.py` (Chromium `/usr/bin/chromium`, временная база и порт 8002). Проверяет общую таблицу, выбор переноса, сравнение, Excel, отказ при повторном использовании резерва и сброс при смене сменности. Снимок — `docs/monitoring.png`.
